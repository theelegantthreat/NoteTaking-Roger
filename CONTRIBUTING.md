# Contributing to NoteTaking-Roger

Thanks for your interest in contributing! We welcome issues, bug reports, feature requests, and pull requests.

## How to contribute

- Open an issue to discuss large changes or new features before starting work.
- For code changes, create a feature branch from `main` named `feature/<short-description>` or `fix/<short-description>`.
- Keep changes small and focused. Include tests where appropriate and update documentation if behavior changes.
- Follow the existing code style and run any linters/tests before opening a pull request.
- Push your branch and open a pull request targeting `main`. In the PR description, explain the problem, the solution, and any steps to test.

## SPDX identifier and file headers

Where practical, add an SPDX short identifier or short license header to new source files, for example:

```
SPDX-License-Identifier: GPL-3.0-or-later
```

This helps tools and downstream users quickly determine licensing.

## Developer sign-off (optional but recommended)

To make contribution provenance clearer, consider adding a sign-off to your commit message (this is similar to the Developer Certificate of Origin):

```
Signed-off-by: Your Name <your.email@example.com>
```

This is not required but helps speed up review and contribution acceptance.
